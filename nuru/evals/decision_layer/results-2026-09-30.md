## Changes made on 2026-09-30

Code and config (`git log` on `thinking-watch` for the exact diffs):

- **Rubrics for all 34 tests** in `score_runs.py`; precise figures (236.8 days, 5.3464 mA) count.
- **Two answered expert calls per turn** (was one). The second answer tells the model it was the
  last, and to ask the user what's unclear if the answers don't settle it; the tool is then taken
  out of the tools offered, and a call made anyway ends the turn with that question to the user
  (the user's choice among three options: give up, ask the user, or ask mid-turn).
- **Expert attachments resolved to vault paths** before the call (the obsidian server's name
  resolution, as `read_note`): a note named by its title now attaches.
- **Failed tool calls logged as errors** in the session log (they were logged `ok`).
- **The repeated-call check ignores case** (`nuru/indexes/x.md` repeats `nuru/Indexes/x.md`).
- **`watch_report.py` counts steers from the decision log** (it showed 0 where there were 8), and
  `run_suite.py` records the session of a run that timed out or crashed, so its decisions match up.
- **Separate switches for the checks decided by code**: `step_cap` (from `tool_gate`),
  `write_checks` (from `gate_write`), and `watch_thinking` (its Laya question moved to
  `watch_laya`). They ask Laya nothing, so they need no calibration.
- **A new `off` mode**: the point isn't asked at all. `assess_effort` is off - every call thinks at
  `THINK=low`; the tier code stays for when Laya is trained.
- **Enforced, at the user's request:** `watch_thinking`, `step_cap` and `write_checks`. The step
  cap is 10 rounds, not 6: 6 would have stopped three passing test 32 runs at low (7-8 rounds);
  past 10 there were only loops (10-24 rounds). Everything that asks Laya stays in shadow.

Not re-benchmarked yet with these enforced.
